判定要点的顺序(先看放大镜)

  • 放大镜里的边框(决定性):A 列的 1.5px 边被 blur(7px) 晕成一条柔和灰雾,内侧还糊进了一圈页面内容;B 列同样内移、同样变短,但边缘始终是干净硬边。
  • 两列几何完全重合:同一组滑块下,边框位置、圆角半径、阴影范围在 A / B 两列里逐像素一致 —— 所以看到任何几何差异都说明实现跑偏了。
  • 圆角拐角是糊得最明显的地方:A 列的直角拐点会被模糊抹圆;B 列的拐角保持锐利,只是半径按 0.976 等比缩了(18px → 约 17.6px,看不出差别)。
  • 把 blur 拉到 22px 再看 B 列:边框依然是硬边。两层保障:browser 自身没有任何 border / outline / 阴影,加上 .browserContainer 的 overflow: clip 把模糊裁在边框内侧。
  • 把 opacity 也调到 0.5:B 列边框不会随之变淡 —— 因为 opacity 和 filter 一起下移了。这正是它必须跟 filter 同层的原因。
  • 页面正好是纯白时:内缩露出的是工作区纸底,边框内侧那条窄缝会是纸色而非页面白,能看见一丝边界;但页面内容本身的内缩仍然不明显 —— 这是真实情况,不是 bug。
  • 本页证明不了的事(务必实机确认):它只能证明"长什么样",证明不了 filter 打在 browser 这一层时 Firefox 的 WebRender 是否照常合成。原注释 userChrome.css:1294-1296 当初选外层正是出于这个顾虑 —— 改完请重载一次 Firefox 亲眼确认模糊仍旧生效。若失效,退路是把 filter 上提一层到 .browserStack(它同样没有 border/outline),而不是退回卡片层。
